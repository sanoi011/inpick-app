# INPICK 도면 → 실별 이미지 생성 파이프라인 감사 보고서

작성일: 2026-07-24  
대상: 아파트 주소·평형 검색 → Step1 도면 분석 → Step2 GPT Image 2 실별 생성

## 결론

기존 파이프라인은 주소에서 실제 평면도 이미지를 찾았더라도 구조 분석 단계에서
`watermark_only` 모드를 사용했다. 이 모드는 실제 이미지의 실 배치 분석 대신
평형·방 개수 기반 평균 구조를 생성한다. 이후 Step2도 전체 도면 그래프를 렌더 API에
보내지 않아 서버가 선택 실 하나의 가로·세로만 가진 사각형으로 다시 축약했다.

따라서 단지와 평면도가 달라도 공간 형태는 평균적인 한국 아파트로 수렴하고,
사용자 스타일이나 주방 마감만 결과 차이로 남았다.

## 확인된 원인

1. 실제 주소 도면이 구조 분석에 사용되지 않음
   - `BasicInfoCard`가 도면 URL이 있을 때 `processingMode: "watermark_only"`를 전송했다.
   - 서버의 `watermark_only` 분기는 `estimateAreaAverageStructure()`를 호출했다.
   - 결과적으로 선택한 도면은 저장·정리에만 쓰이고 실 좌표 분석에는 쓰이지 않았다.

2. 도면 분석 완료 전 Step2 진입 가능
   - 주소 모드는 `normalizing` 중이어도 다음 버튼이 활성화됐다.
   - Step2가 먼저 마운트되면 평형 평균 치수가 생성 기준으로 고정됐다.

3. 전체 세대 구조가 렌더 API에서 유실
   - Step2 요청에는 선택 실의 `widthMm/depthMm`과 자유 형식 `wallLayout`만 있었다.
   - Step1의 전체 `normalizedFloorplan` 또는 파싱된 실 그래프는 보내지 않았다.
   - 서버 `RenderRoomSpec`은 전체 도면이 없을 때 선택 실 하나만 있는 최소 spec을 만들었다.

4. 실 이름 불일치가 평균값 또는 거실값 폴백을 유발
   - UI는 `부엌`, 도면은 `주방`을 사용한다.
   - 도면은 `욕실1`, `침실1`인데 UI는 `욕실`, `침실`을 사용한다.
   - 정확 문자열 일치가 실패하면 선택 실 대신 평형 평균 또는 거실 치수를 사용했다.

5. 기본 프롬프트가 전형적인 구조를 강제
   - 거실은 항상 TV 벽과 발코니 통창 구성을 요구했다.
   - 주방은 항상 U자 또는 L자 구성을 요구했다.
   - 이 문장이 실제 도면보다 강한 시각적 사전값으로 작동했다.

6. 제품 선택 데이터가 새 생성에도 재주입
   - 이전에 저장된 실제 제품/SKU 선택값이 새 이미지 prompt에 자동 합쳐질 수 있었다.
   - 구조 차이보다 마감 차이가 더 두드러지는 결과를 만들었다.

## 수정된 파이프라인

```text
주소·평형에서 실제 도면 선택
  → Step1 structure_only 정밀 VLM 분석
  → 실 이름 + mm 치수 + x/y + polygon + 문/창호 연결 실 추출
  → 분석 완료 전 Step2 진입 차단
  → UI 실 이름을 도면 실 종류로 정규화
  → 전체 세대 room graph + openings를 RenderRoomSpec으로 전달
  → 선택 실 전용 FLOORPLAN EVIDENCE prompt 생성
  → GPT Image 2에 도면 이미지 + 구조 명세 + 실별 사용자 prompt 전달
```

구조 우선순위는 다음과 같다.

1. 실제 도면에서 검출한 polygon·bbox·문·창호
2. 실제 도면에서 검출한 실 치수와 전체 실 목록
3. 사용자가 선택한 기본형/확장형
4. 실별 사용자 스타일 prompt
5. 도면이 없는 경우에만 평형 평균

실제 도면 분석이 실패하거나 선택 실을 찾지 못하면 평형 평균으로 조용히 생성하지 않고
Step1 재분석을 요청한다. 실제 도면에 검출되지 않은 평균 실 목록도 자동 추가하지 않는다.

## 공개 UI 정책

- 실제 제품/SKU 경계 선택·이미지 교체 UI: 비공개
- 저장된 과거 제품/SKU의 신규 이미지 prompt 자동 주입: 중지
- 코드는 삭제하지 않고 `ROOM_PRODUCT_CUSTOMIZATION_ENABLED=false`로 유지
- 전체 공통 prompt와 거실·부엌·욕실·침실 등 실별 prompt: 각각 독립 저장·적용

## 남은 기술적 한계

GPT Image 2는 2D 평면도를 3D 카메라 장면으로 정확히 투영하는 전용 CAD 렌더러가 아니다.
이번 수정은 실제 도면이 파이프라인에서 유실되는 오류와 전형 레이아웃 강제를 제거하지만,
polygon을 픽셀 단위로 완전히 보존하는 것을 보장하지는 않는다.

출시 후에는 다음 지표를 별도로 측정해야 한다.

- 선택 실 분류 정확도
- 실 가로:세로 비율 오차
- 문·창호 개수 및 벽 방향 일치율
- 욕실/침실 요청이 거실 장면으로 변환되는 오류율
- 동일 스타일·상이한 도면 쌍의 구조 차이 점수

정확한 벽 좌표 보존이 필요한 단계에서는 도면 polygon으로 먼저 3D shell/depth map을 만든 뒤
이미지 모델을 마감 렌더러로만 사용하는 geometry-conditioned 파이프라인이 필요하다.
